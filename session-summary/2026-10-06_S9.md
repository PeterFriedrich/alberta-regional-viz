## 3. Technical Learnings
- **www12.statcan.gc.ca serves this box a Cloudflare challenge** ("Just a moment…"). Census highlight tables come through Wayback instead:
  - `https://web.archive.org/web/<ts>id_/<url>`.
  - The CDX API finds captures (`matchType=prefix&collapse=urlkey`).
  - 2016: `.../2016/dp-pd/hlt-fst/pd-pl/Tables/CompFile.cfm?Lang=Eng&T=301&OFT=FULLCSV`.
  - 2011: `File.cfm?T=302&...&PR=48...&OFT=CSV`.
  - 2006: `Index.cfm?TPL=P1C&Page=RETR&LANG=Eng&T=302&...&RPP=9999&PR=48` (HTML).
  - 2001: `Table-CSD-P.cfm?T=1&PR=48&SR=<1..451>`, 19 pages.
  - www150 (WDS, 92F0009X) works directly.
- **92F0009X change codes:**
  - 5/6 are annexations, 5A/4 dissolutions.
  - **8/9 and 8C/9C are StatCan boundary corrections, and 10/11 population revisions. Neither is a legal change.** Chestermere's +442 in 2001 is code 8.
  - The 2016+ HTML tables give one row per pair, with "Census Population Affected" and the effective date.
  - The 2006–11 list is a CSV: `2011001/tbl/csv/92F0009XIB2011001_T1_48.csv`.
- **Census windows don't follow effective dates alone.** Two changes effective 2006-01-01 fall in different windows: Stony Plain in 2001–06, Devon in 2006–11. So `annexations.csv` carries `change_list`.
- **17-10-0142 vs 0155 differ by more than boundaries in non-census years.** Vintage revisions add noise, e.g. Calgary +667 in 2001 with no annexation. Only 2011 is clean.
- **`fir_long.csv` POPL has one row per FIR code.** An absorbed village, e.g. New Sarepta 0234, sits under its member's `muni_id`. Key by `fir_code` or you will overwrite rows.
- **The Claude Docs connector is in use.** The doc's project id is `103a677b-c1bd-4b21-8b96-d423b4bf8833`, its prose root node `a76c3cd9-48cc`.
